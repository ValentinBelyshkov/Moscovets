# Исправление ошибки загрузки DICOM файлов в DWV

## Краткое описание

Добавлено детальное логирование и диагностику для выявления и исправления ошибки загрузки DICOM файлов после распаковки ZIP архива.

## Измененные файлы

### 1. `frontend/src/components/DWVViewer.js`

**Основные изменения:**

#### Улучшенная инициализация DWV
- Детальное логирование создания экземпляра DWV App
- Логирование конфигурации инициализации
- Логирование установки инструментов
- Детальное логирование ошибок инициализации

#### Расширенные обработчики событий DWV
Добавлены обработчики с полным логированием:
- **loadstart** - начало загрузки файлов
- **loadprogress** - прогресс с процентами и деталями
- **load** - успешная загрузка с метаданными
- **loadend** - завершение загрузки
- **loaditem** - загрузка отдельных файлов (для серий)
- **error** - детальная обработка ошибок с:
  - Типом ошибки
  - Сообщением
  - Деталировкой
  - Информацией о проблемном файле

#### Валидация файлов перед загрузкой
- Логирование всех входящих файлов с полной информацией
- Фильтрация только DICOM файлов (.dcm, .dicom)
- Проверка размера файлов (не 0 байт)
- Проверка типа объекта (File)
- Try-catch вокруг `app.loadFiles()` с детальным выводом

#### Улучшенное сообщение об ошибке
Формируется детальное сообщение для пользователя:
```
Не удалось обработать DICOM файлы
Ошибка: <тип ошибки>
Тип: <название ошибки>
Файлов: <количество>
Первый файл: <имя> (<размер> bytes, <тип>)
```

#### Cleanup логирование
- Логирование удаления DWV приложения
- Обработка ошибок при dispose

### 2. `frontend/src/components/CTModule.js`

**Основные изменения:**

#### Новая функция `validateDicomFiles()`
Валидация DICOM файлов перед передачей в DWV:
- Проверка instanceof File
- Проверка наличия имени файла
- Проверка расширения (.dcm или .dicom)
- Проверка размера (не 0 байт)
- Попытка чтения первых 132 байт (DICOM preamble)
- Возвращает `{ valid, errors, validFiles }`

#### Детальное логирование `processZipArchive()`
- Логирование каждого этапа обработки ZIP
- Логирование свойств ZIP entries
- Лог создания Blob из ZIP entry
- Лог создания File из Blob
- Статистика извлеченных файлов
- Логирование сортировки файлов

#### Детальное логирование `loadFilesFromBlobs()`
- Логирование восстановления файлов из localStorage
- Проверка целостности данных
- Логирование создания Blob/File объектов
- Сравнение размеров до/после

#### Детальное логирование `handleLoadDICOM()`
- Логирование количества файлов
- Логирование конвертации в ArrayBuffer
- Проверка целостности данных при конвертации
- Логирование сохранения в localStorage
- Логирование установки состояния

#### Интеграция валидации перед DWV
- Вызов validateDicomFiles() перед рендерингом DWVViewer
- Отображение детального списка ошибок при проблемах
- Блокировка передачи некорректных файлов

## Как использовать

### 1. Тестирование
```bash
cd frontend
npm start
# Откройте http://localhost:3630
# Перейдите в модуль КТ
# Загрузите ZIP архив
# Нажмите "Открыть в просмотрщике"
```

### 2. Анализ логов
Откройте консоль браузера (F12) и используйте фильтры:
- `[DWV]` - логи из DWVViewer.js
- `[CTModule]` - логи из CTModule.js
- `[DWV] error` - только ошибки DWV
- `error` - все ошибки

### 3. При ошибке
1. Соберите логи из консоли
2. Сделайте скриншот Network tab (фильтр: blob:)
3. Проанализируйте ошибку
