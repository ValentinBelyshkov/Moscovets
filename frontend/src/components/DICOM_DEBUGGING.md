# Отладка загрузки DICOM файлов в DWV

## Описание проблемы

После распаковки ZIP архива с DICOM файлами на клиенте:
- DWV viewer не открывается
- Появляется ошибка "Не удалось обработать DICOM файлы"
- В Network видны blob URL запросы типа `blob:http://localhost:3630/...`

## Выполненные изменения для диагностики

### 1. DWVViewer.js - детальное логирование

#### Инициализация DWV
- Логирование создания экземпляра DWV App
- Логирование конфигурации инициализации
- Логирование установки начального инструмента
- Детальный вывод ошибок инициализации с stack trace

#### События загрузки файлов
Добавлены обработчики событий с детальным логированием:

- **loadstart**: Начало загрузки
- **loadprogress**: Прогресс загрузки с процентами
- **load**: Успешная загрузка файла
- **loadend**: Завершение загрузки
- **loaditem**: Загрузка отдельного файла (для серий)
- **error**: Обработка ошибок с детализацией:
  - Название события
  - Сообщение об ошибке
  - Тип ошибки
  - Детали ошибки
  - Информация о файле

#### Валидация и загрузка файлов
- Логирование всех входящих файлов с:
  - Имя файла
  - Размер
  - Тип MIME
  - Время модификации
  - Конструктор объекта
- Фильтрация DICOM файлов с логированием пропущенных файлов
- Валидация размера файлов (проверка на 0 байт)
- Проверка типа объекта (File)
- Try-catch вокруг `app.loadFiles()` с детальным выводом ошибок

#### Сообщение об ошибке
Формируется детальное сообщение, включающее:
- "Не удалось обработать DICOM файлы"
- Тип ошибки
- Сообщение ошибки
- Детали ошибки
- Информация о проблемном файле (имя, размер, тип)

### 2. CTModule.js - логирование процесса обработки ZIP

#### processZipArchive()
Логирование каждого этапа:
- Начало обработки архива (имя, размер, тип)
- Загрузка ZIP структуры
- Обработка каждого файла:
  - Извлечение из архива
  - Создание Blob
  - Создание File объекта
- Сортировка файлов
- Итоговая статистика

#### loadFilesFromBlobs()
Логирование восстановления файлов из localStorage:
- Количество blob данных
- Детали каждого восстанавливаемого файла
- Создание Blob и File объектов
- Успешное восстановление

#### handleLoadDICOM()
Логирование подготовки файлов к просмотру:
- Количество файлов
- Конвертация в ArrayBuffer
- Сохранение в localStorage
- Установка состояния с файлами

#### validateDicomFiles()
Новая функция валидации DICOM файлов:
- Проверка что это File объект
- Проверка имени файла
- Проверка расширения (.dcm или .dicom)
- Проверка размера (не 0 байт)
- Попытка чтения первых 132 байт (DICOM preamble)
- Возвращает объект с результатами валидации:
  - valid: boolean
  - errors: array of strings
  - validFiles: array of File objects

#### Валидация перед передачей в DWV
Перед рендерингом DWVViewer:
- Вызывается валидация файлов
- При ошибках валидации отображается детальный список ошибок
- При успешной валидации файлы передаются в DWV

## Использование отладочных логов

### Открытие консоли браузера
1. Нажмите F12 или Ctrl+Shift+I (Cmd+Option+I на Mac)
2. Перейдите на вкладку Console

### Фильтрация логов
Для удобства используйте фильтр по префиксам:
- `[DWV]` - логи из DWVViewer.js
- `[CTModule]` - логи из CTModule.js

Примеры фильтров:
```
[DWV]
[CTModule]
[DWV] error
```

### Поиск проблем по логам

#### Если ошибка "Не найдено DICOM файлов"
- Проверьте, что файлы имеют правильное расширение (.dcm или .dicom)
- Проверьте, что тип MIME установлен как 'application/dicom'

#### Если ошибка "Файл имеет размер 0 байт"
- Архив может быть поврежден
- Файл не был правильно извлечен из ZIP
- Проверьте логи процесса извлечения

#### Если ошибка при app.loadFiles()
- Проверьте, что файлы являются File объектами
- Проверьте, что файлы читаются (можно открыть в hex редакторе)
- Проверьте blob URL запросы в Network tab

#### Если ошибки валидации перед передачей в DWV
- Красный блок с ошибками появится вместо DWV viewer
- Каждая ошибка содержит детальное описание проблемы
- Проверьте типы, размеры, имена файлов

## Возможные причины ошибок и решения

### 1. File объекты после localStorage
**Проблема:** При восстановлении файлов из localStorage теряются внутренние свойства File.

**Решение:** Проверьте логи `[CTModule] File object reconstructed`. Сравните с оригинальными логами создания файлов.

### 2. Тип MIME
**Проблема:** DWV не распознает файлы без правильного MIME типа.

**Решение:** Убедитесь, что все файлы имеют `type: 'application/dicom'`.

### 3. Размер файлов
**Проблема:** Файлы с размером 0 или NaN вызывают ошибки DWV.

**Решение:** Валидация фильтрует такие файлы и выводит ошибки.

### 4. Порядок файлов
**Проблема:** Неправильный порядок срезов в серии DICOM.

**Решение:** Файлы сортируются по имени. Если порядок неправильный, проверьте имена файлов.

### 5. Слишком большие файлы
**Проблема:** Браузер не может обработать большие файлы.

**Решение:** Разбейте архив на несколько частей или используйте меньшее количество срезов.

## Следующие шаги

1. Откройте консоль браузера
2. Загрузите ZIP архив с DICOM файлами
3. Нажмите "Открыть в просмотрщике"
4. Соберите логи из консоли
5. При появлении ошибки:
   - Посмотрите точное сообщение об ошибке
   - Проверьте логи перед ошибкой
   - Ищите красные сообщения об ошибках
6. Проанализируйте логи согласно этому документу

## Контакт

Если проблема не решена:
1. Соберите все логи из консоли
2. Сделайте скриншот Network tab (фильтр: blob:)
3. Сохраните скриншот ошибки в UI
4. Предоставьте всю информацию для анализа
